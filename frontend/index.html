              Kategorien (Hauptgruppen)

              Ihre Standard-Funktionskategorien. Reihenfolge = Hauptgruppennummer. Normalerweise einmalig festgelegt und danach unverändert. Das Adressierungsschema selbst (Hauptgruppe = Kategorie, Mittelgruppe = Geschoss, Untergruppe = Punkt) ist fest im Tool verankert, nicht nur hier in der Reihenfolge — ein anderes Schema (z.B. Geschoss als Hauptgruppe) würde eine andere Tool-Variante erfordern, siehe Hilfe-Tab. Deshalb gibt es hier bewusst kein Hinzufügen/Löschen, nur Umbenennen: es sind immer genau 6, jede an einer festen Hauptgruppennummer.

                Funktionstypen

                Wiederverwendbare Bausteine (ein Licht, eine Jalousie, eine Steckdose...) mit ihren Datenpunkten und reserviertem Blockumfang. Ein Funktionstyp bestimmt, welche Untergruppen entstehen, wenn er im Funktionen-Unterreiter einem Raum zugewiesen wird (z.B. erzeugt "Licht (Dimmen)" die Datenpunkte Schalten/Status/Dimmen unter einer eigenen Adresse je Raum/Label). Der "Kanaltyp" verknüpft einen Punkt mit passenden Aktortypen weiter unten, damit er in der Abgangsliste eines Projekts einem physischen Aktorkanal zugeordnet werden kann. Die vorbelegten Funktionstypen sind ein Vorschlag, kein festes Schema — Datenpunkte/Suffixe/DPTs frei anpassen, oder unten den kompletten Satz löschen und eigene anlegen.

                  Zentral-/Allgemeinfunktions-Vorlagen

                  Werden in jedem Projekt automatisch erzeugt, ohne dass Sie sie pro Projekt anlegen müssen — je Kategorie entstehen daraus die "Zentralfunktionen"-Mittelgruppe(n) bzw., bei der Kategorie Allgemein, eigene Mittelgruppen (z.B. Datum/Uhrzeit, Klima). Geltungsbereich "building" = ein Block für das ganze Projekt. "floor" = ein Block je Geschoss (z.B. "Zentral EG", "Zentral OG"). "room_multi" = ein Block PRO RAUM, nur für Räume mit mehreren Punkten dieser Kategorie (z.B. erhält ein Raum mit 2+ Jalousien eine eigene kombinierte "Zentral"-Steuerung). Wie bei Funktionstypen sind auch dies nur Vorschläge — frei anpassen oder unten den kompletten Satz löschen, um eigene Sammel-/Zentralfunktionen von Grund auf zu definieren.

                    Backup i

                    Automatische und/oder manuelle Sicherung auf ein NAS/gemountetes Verzeichnis und/oder Nextcloud — beide Ziele lassen sich unabhängig voneinander aktivieren.

                    NAS / gemountetes Verzeichnis

                    Das Verzeichnis muss im Container erreichbar sein, z.B. per Bind-Mount in docker-compose.yml auf einen NAS-Freigabe-Pfad (siehe DEPLOYMENT.md).

                    Nextcloud (WebDAV)

                    i

                    Vorhandene Sicherungen

                    Listet Sicherungen aus jedem aktivierten Ziel (NAS/gemountetes Verzeichnis und/oder Nextcloud).

                      Sicherung wiederherstellen (Datei hochladen)

                      Ersetzt die komplette aktuelle Datenbank durch den Inhalt der hochgeladenen Datei — vorher wird automatisch eine Sicherung des aktuellen Stands angelegt, danach startet die App neu.

                      Update

                      Prüft per Git, ob auf GitHub eine neuere Version vorliegt als die aktuell laufende. Es wird nichts automatisch im Hintergrund geprüft — nur auf Klick.
